\begin{abstract}
A \abstdefterm{path coloring} of a graph $G$ is a vertex coloring
of $G$ such that each color class induces a disjoint union of paths.
We present two efficient algorithms
to construct a path coloring of a plane graph.

The first algorithm, based on a proof of Poh, %\cite{Poh1990}
is given a plane graph, and
produces a path coloring of the given graph
using three colors.

The second algorithm,
based on similar proofs
by Hartman % \cite{Har1997}
and \v{S}krekovski, %\cite{Skr1999}
performs a list-coloring generalization of the above.
The algorithm is given a plane graph and an assignment of lists of
three colors to each vertex, and it
it produces a path coloring of the given graph
in which each vertex receives a color from its list.

Implementations are available for all algorithms that are described.
\end{abstract}

\section{Introduction}

A \defterm{(finite, simple) graph} $G=(V,E)$ is a finite set $V(G)$ of
\defterm{vertices}
and a set $E(G)$ of \defterm{edges}: unordered pairs of vertices.
We write $n(G)=|V(G)|$
and $m(G)=|E(G)|$ for the number of vertices and edges, respectively.
Vertices
$u,v\in V(G)$ are \defterm{neighbors} if $uv\in E(G)$; we say $u,v$ are
\defterm{incident} to $uv$. We write $N(v)$ for the set of neighbors of $v$.
The degree of $v$ is $\text{deg}(v)=|N(v)|$.
We write $v\in G$ or $uv\in G$ if it is clear
$v$ is a vertex or $uv$ is an edge.

We say $H$ is a \defterm{subgraph} of $G$ if
$V(H)\subseteq V(G)$ and $E(H)\subseteq E(G)$. If $S\subseteq V(G)$,
the subgraph of $G$ \defterm{induced} by $S$ consists
of $S$ and all edges in $E(G)$ with both incident vertices in $S$.
Let $H,K$ be subgraphs of $G$.
We say $H$ and $K$ are \defterm{disjoint} if $V(H)\cap V(K)=\emptyset$
(the vertex sets are disjoint).
The union $H\cup K$ is the union
of their edge and vertex sets. The difference $H-K$ is
the subgraph of $H$ induced by $V(H)- V(K)$.
If $u,v\in V(H)$, $uv\in E(G)$, we
define $H\cup uv$ and $H-uv$ by adding/removing the edge $uv$
to/from $E(H)$.

A graph is
\defterm{planar} if it may be drawn in the plane by mapping
each vertex to a point and each edge to a curve connecting the points of
its incident vertices such that curves intersect only at their
endpoints. A \defterm{face} is a maximal region
of the plane not containing any point of the drawing; we
will always refer to a face by the vertices and edges mapped on
its border. The unbounded face is the \defterm{outer face}. 
A \defterm{(combinatorial) embedding} (or \defterm{rotation scheme})
is an equivalence
class of drawings determined by the circular ordering of edges
around each vertex. A \defterm{plane graph} is a planar graph
with a fixed embedding. Subgraphs of a plane graph are
also plane graphs with the inherited embedding.

A \defterm{path} $P=v_1,v_2,\ldots,v_k$ is the graph with
$V(P)=\{v_1,v_2,\ldots,v_k\}$ and
$E(P)=\{v_1v_2,v_2v_3,\ldots,v_{k-1}v_k\}$; we say $P$ is a
$v_1,v_k$-path. A \defterm{cycle}
$C=v_1,v_2,\ldots,v_k$ is the union of a $v_1,v_k$-path
and the edge $v_1v_k$. The \defterm{length} of a path or cycle is
the number of edges.

A \defterm{(vertex) coloring} of a graph $G$ is a map
$c:V(G)\to\mathbb{N}$; a $k$-coloring, $k\in\mathbb{N}$,
is a map $c:V(G)\to\{1,2,\ldots,k\}$. The \defterm{color class} of
$d\in\mathbb{N}$
is the set $c^{-1}(d)\subseteq V(G)$. A \defterm{path coloring}
is a coloring where each color class induces a union of disjoint
paths (more commonly a \emph{disjoint union} of paths,
but the union of disjoint subgraphs is their disjoint union).
A graph $G$ is \defterm{path $k$-colorable} if $G$
admits a path $k$-coloring.
A \defterm{list assignment} of a graph $G$ is
a map $L:V(G)\to \mathcal{P}_{\text{fin}}(\mathbb{N})$ assigning
a finite set of colors to each vertex. An
\defterm{$L$-coloring} (or \defterm{$L$-list-coloring}) of $G$ is a
coloring $c:V(G)\to\mathbb{N}$ such that $c(v)\in L(v)$ for each $v\in V(G)$.
A graph is \defterm{path $k$-choosable} if it admits a path $L$-coloring
for any list assignment $L$ with at least $k$ colors in each list,
i.e. $|L(v)|\ge k$ for each $v\in G$.

See West~\cite{Wes2000} for a more thorough overview of graph
theoretic terms.

Broere \& Mynhardt conjectured~\cite[Conj.~16]{BrMy1985}
that every planar graph is path $3$-colorable.
This was proven independently by Poh~\cite[Thm.~2]{Poh1990}
and by Goddard~\cite[Thm.~1]{God1991}.

\begin{theorem}[Poh 1990, Goddard 1991]\label{T:planar3c}
If $G$ is a planar graph,
then $G$ is path $3$-colorable.\ggcnopf\end{theorem}

It is easily shown that the ``$3$'' in Theorem~\ref{T:planar3c}
is best possible.
In particular, Chartrand \& Kronk~\cite[Section~3]{ChKr1969}
gave an example of a planar graph whose vertex set cannot be partitioned
into two subsets, each inducing a forest.

Hartman~\cite[Thm.~4.1]{Har1997}
proved a list-coloring generalization of Theorem~\ref{T:planar3c}
(see also Chappell \& Hartman~\cite[Thm.~2.1]{ChHa2017prep}).

\begin{theorem}[Hartman 1997]\label{T:planar3}
If $G$ is a planar graph,
then $G$ is path $3$-choosable.\ggcnopf\end{theorem}

Essentially the same technique was used by
\v{S}krekovski~\cite[Thm.~2.2b]{Skr1999}
to prove a result slightly weaker than Theorem~\ref{T:planar3}.


\medskip

We discuss two path coloring algorithms
based on proofs of the above theorems.

In Section~\ref{S:representation} we outline our graph representations
and the basis for our computations of time complexity.

Section~\ref{S:path_color} covers an algorithm
based on Poh's proof of Theorem~\ref{T:planar3c}.
The algorithm is given a plane graph;
it produces a path coloring of the given graph
using three colors.

Section~\ref{S:path_choose} covers an algorithm
based Hartman's proof of Theorem~\ref{T:planar3},
along with the proof of \v{S}krekovski mentioned above.
The algorithm is given a plane graph
and an assignment of a list of three colors to each vertex;
it produces a path coloring of the given graph
in which each vertex receives a color from its list.

Section~\ref{S:performance} provides benchmark results for
implementations of each algorithm~\cite{Bro2017}. The section also
discusses how each algorithm may be modified to benefit from parallelism.


\section{Graph Representations and Time Complexity}\label{S:representation}

A graph $G$ is \defterm{connected} if given any $u,v\in G$, there exists a
$u,v$-path in $G$,
and \defterm{biconnected} if $G-v$ is connected
for every $v\in G$.
A plane graph $G$ is \defterm{triangulated} if it is connected
and $n(G)\le 2$, or if every face is a
\defterm{triangle} (a length $3$ cycle). If every face but
(maybe) the
outer face is a triangle, then $G$ is
\defterm{weakly triangulated}; a triangulated graph is weakly-triangulated.
If $G$ is biconnected and $n(G)\ge 3$, then its outer face is a cycle.

The input for each algorithm will be a biconnected, weakly triangulated
plane graph $G$ with $n$ vertices and $m$ edges.
The input size will be $n$. By Euler's formula
$m\le 3n-6$, with
$m=3n-6$ if $G$ is triangulated, so $\mathcal{O}(m)=\mathcal{O}(n)$ and
it is equivalent to take the input size
to be $m$.
Arbitrary planar graphs may be
plane embedded and triangulated (by adding edges) in $\mathcal{O}(n)$ time, see e.g. Hopcroft
and Tarjan~\cite{Hop1974} or Boyer and
Myrvold~\cite{BoMy2004}.

We will represent $G$ for computation via \textit{adjacency lists}:
a list, for each vertex $v$, of the neighbors of $v$.
A vertex is represented by an integer $0\dots n-1$.
The order of each list represents the embedding. In algorithms
$N(v)$ will refer to the adacency list.

Let $v\in G$ and $u\in N(v)$. Define $\nxt_v(u)\in N(v)$ to be
the neighbor counter-clockwise from $u$ around $v$,
and $\prv_v(u)\in N(V)$ the neighbor clockwise from $u$.
In algorithms
$\adj{v}{u}$ will be a reference to $u$'s entry in $N(v)$, i.e.
$\adj{v}{u}$ represents both $u$ and the position of $u$ in $v$'s
adjacency list;
define $\nxt(\adj{v}{u})=\adj{v}{(\nxt_v(u))}$ and
$\prv(\adj{v}{u})=\adj{v}{(\prv_v(u))}$.

In Section~\ref{S:path_color} we'll only need our representation to be
able to compute $\nxt(\adj{v}{u})$ in constant time from $\adj{v}{u}$.
In Section~\ref{S:path_choose} however, we'll also need the ability to
find $\prv(\adj{v}{u})$ and the \defterm{back reference} $\adj{u}{v}$
from $\adj{v}{u}$ in constant time.
Representing $N(v)$ via an array or
doubly linked list solves computing $\prv(\adj{v}{u})$, but
back references require a different representation.
We define an \defterm{augmented adjacency list} to be an adjacency
list that stores the pair $(u,\adj{u}{v})$ for each neighbor $u$ of $v$,
rather than just the vertex $u$. Given an
adjacency list representation, an augmented
representation may be constructed in $\mathcal{O}(m)$ time. 

\begin{algorithm}\label{A:augment} Augment Adjacency Lists

\textbf{Input.} An adjacency list representation $N$ of a graph $G$.

\textbf{Output.} An augmented adjacency list representation $N^*$ of
$G$ with the same rotation scheme as $N$.

\textbf{Step~1.} For each $v\in G$ construct an
augmented adjacency list $N^*(v)$
with the rotation scheme of $N(v)$, leaving the
$\adj{u}{v}$ portion of each entry $(u,\adj{u}{v})$ in $N^*(v)$
uninitialized.

\textbf{Step~2.} For each vertex $v$ construct an array $\text{Wrk}(v)$
of vertex-reference pairs with length $\text{deg}(v)$. For each $v$ from
$0$ to $n-1$ iterate through
$N^*(v)$. For each neighbor $u$ in $N^*(v)$ append the pair
$(v,\adj{v}{u})$ to $\text{Wrk}(u)$,
where $\adj{v}{u}$ is a reference to $u$'s entry $N^*(v)$.

\textbf{Step~3.} For each $v$ from $n-1$ to $0$ iterate through
$\text{Wrk}(v)$. Upon reaching a pair $(u,\adj{u}{v})$ in
$\text{Wrk}(v)$ the
last element of $\text{Wrk}(u)$ will be $(v,\adj{v}{u})$;
see the below. Lookup the entry $\adj{v}{u}$ in $N^*(v)$ and
initialize the back reference $\adj{u}{v}$, and vice versa.
Remove $(v,\adj{v}{u})$ from the back of $\text{Wrk}(u)$.
\end{algorithm}

After completing Step~2 in Algorithm~\ref{A:augment} the array $\text{Wrk}(v)$
will contain
$(u,\adj{u}{v})$ for each neighbor $u$ of $v$, sorted in increasing
order by the neighbor $u$.
Suppose that $v$ is the current vertex at a given iteration of Step~3 in
Algorithm~\ref{A:augment}. For each edge $uw\in E(G)$ such that
$u<w$ and $v<w$, prior iterations of Step~3 will have initialized the
back references for $\adj{w}{u}$ in $N^*(u)$ and $\adj{u}{w}$ in $N^*(w)$,
and removed the pair
$(w,\adj{w}{u})$ from $\text{Wrk}(u)$. Therefore for each
$(u,\adj{u}{v})$ in
$\text{Wrk}(v)$, the array $\text{Wrk}(u)$ will contain only entries for
vertices $w$ where $w\le v$. So the last element of
$\text{Wrk}(u)$ must be $(v,\adj{v}{u})$.

\section{Path Coloring}\label{S:path_color}

In this section we describe a linear time algorithm to path $3$-color
plane graphs. Let's first recount Poh's path $3$-coloring strategy.

Let $C$ be a cycle in a plane graph $G$. If $u,v\in C$, then we define
$C[u,v]$ to be the clockwise $u,v$-path
around $C$; if $u=v$, then $C[u,u]=u$.
Define $\text{Int}(C)$ to
be the subgraph of $G$ consisting of $C$ and all vertices and edges interior to
$C$; equivalently, $\text{Int}(C)$ is the maximal subgraph of
$G$ with outer face $C$.

Let $P$ be a path in a plane graph $G$. If $u,v\in P$, then
we define $P[u,v]$ to be the $u,v$-path in $P$.
We define $\text{Int}(P)=P$.

\begin{lemma}[Poh 1990]\label{L:planar3c}
Let $G$ be a biconnected, weakly triangulated plane graph with outer face
$C$. Let $c:V(C)\to S\subsetneq\{1,2,3\}$ be a $2$-coloring of $C$ such
that each color class induces a nonempty path. There exists an extension of
$c$ to a path $3$-coloring $c:V(G)\to\{1,2,3\}$ such that for each $v\in G-C$, if $vu\in
E(G)$ with $u\in C$, then $c(v)\ne c(u)$.
\end{lemma}

\begin{proof}
If $n(G)\le 3$, then $G=C$ and the path $2$-coloring of $C$ is a path
$3$-coloring of $G$. We proceed by induction on the order of $G$. 

Let $P_1,P_2$ be the two paths induced by the $2$-coloring of the outer face
$C$. We may write $P_1=C[u_1,w_1]$ and $P_2=C[w_2,u_2]$ for vertices
$u_1,u_2,w_1,w_2\in C$.

Suppose $C$ is an induced subgraph of $G$. Let
$u,w\in G-C$ be the vertices such that the cycles
$u,u_2,u_1$ and $w,w_1,w_2$ are faces of $G$; note that
$u$ and $w$ are uniquely determined, but it may be that $u=w$. Since
$C$ is an induced cycle in $G$, and $G\ne C$, $G-C$ is connected.
Let $P_3$ be a $u,w$-path in $G-C$ of minimal length, and
note that $P_3$ is an induced subgraph of $G-C$.
Color each vertex of $P_3$ with the color in $\{1,2,3\}- S$ not used
in the $2$-coloring of
$C$. Let $C_1=P_1\cup P_3\cup uu_1\cup ww_1$ and
$C_2=P_2\cup P_3\cup uu_2\cup ww_2$. The subgraphs
$\text{Int}(C_1)$ and $\text{Int}(C_2)$ together with the coloring $c$
each satisfy the requirements of the lemma. By the inductive hypothesis
there exist extensions of $c$ to a path
$3$-coloring of $\text{Int}(C_1)$ and a path $3$-coloring of $\text{Int}(C_2)$.
Since $\text{Int}(C_1)$ and $\text{Int}(C_2)$ only share the vertices in $P_3$
on their respective outer faces, the colorings agree and form a path
$3$-coloring of $G$.

Suppose $C$ is not an induced subgraph. Then there
exists an edge $v_1v_2\in E(G)- E(C)$ with $v_1\in P_1$ and
$v_2\in P_2$. Let $C_1=C[v_2,v_1]\cup v_1v_2$
and $C_2=C[v_1,v_2]\cup v_1v_2$.
By the inductive hypothesis, there exists an extension of $c$ to a path
$3$-coloring of $\text{Int}(C_1)$ and $\text{Int}(C_2)$. Again
the subgraphs only share vertices on their outer faces, and thus the
colorings agree and together form a path $3$-coloring of $G$.\ggcnopf
\end{proof}

Let $G$ be a triangulated plane graph. We may trivially path $2$-color the outer
triangle. By Lemma~\ref{L:planar3c} this extends to a path
$3$-coloring of $G$.
If $G$ is an arbitrary planar graph, we may compute an embedding and add edges
to produce a triangulated plane graph $G'$. Theorem~\ref{T:planar3c}
follows immediately as any path coloring of
$G'$ is also a path coloring of $G$.

A natural way to implement Poh's algorithm is to locate $u$,
and then use a breadth-first search to construct a minimal
$u,w$-path and/or locate a chord edge, see Algorithm~\ref{A:poh_bfs}.

\begin{algorithm}\label{A:poh_bfs} Path $3$-Color (BFS)

\textbf{Input.} 
Let $C$ be a cycle or length $1$ path
in a weakly triangulated plane graph $G$ represented via adjacency lists.
Let  $c$ be a length $n$ array representing a $2$-coloring of $C$ such
that each color class induces a nonempty path, respectively
$P_1=C[u_1,w_1]$ and $P_2=C[w_2,u_2]$ for $u_1,u_2,w_1,w_2\in C$.
Assume $c(v)=0$ for each $v\in\text{Int}(C)-C$.

The concrete input will be $G$, $c$, and the tuple
$(u_1, w_1, \adj{{u_1}}{u_2}, w_2)$. 

\textbf{Output.} For each vertex $v\in\text{Int}(C)-C$, a color in
$\{1,2,3\}$ will be
assigned to $c(v)$ such that $c$ represents a path $3$-coloring of
$\text{Int}(C)$ extending the original $2$-coloring of $C$. Moreover, if
$v\in \text{Int}(C)-C$ has a neighbor $u\in C$, then $c(v)\ne c(u)$.

\textbf{Base case.} If $u_1=w_1$ and $u_2=w_2$, then $C$ is a length
$1$ path and $\text{Int}(C)=C$.

\textbf{Recursive case.}
Let $\adj{{u_1}}{u}\leftarrow\nxt(\adj{{u_1}}{u_2})$.
Note that $u,u_2,u_1$ is a face of $G$, see Figure~\ref{F:poh_bfs}.

\textbf{Case~1.} Suppose that $c(u)\ne 0$.
If $c(u)=c(u_2)$, then $u\in P_2$.
Make a recursive call with the input $(u_1, w_1, \adj{u_1}{u}, w_2)$
to color
$\text{Int}(C_1)$ where $C_1=C[u_1,u]\cup u_1u$. Otherwise, $c(u)=c(v_1)$ and
$u\in P_1$. Iterate through $N(u)$ to find $\adj{u}{u_2}$.
Make a recursive call with the input
$(u, w_1, \adj{u}{u_2}, w_2)$
to color $\text{Int}(C_1)$, where $C_1=C[u,u_2]\cup uu_2$. 

\textbf{Case~2.} Suppose that $c(u)=0$, i.e. $u\in \text{Int}(C)-C$.
Perform a breadth-first search in $\text{Int}(C)-C$ starting from $u$;
such a search may be implemented by visiting $v\in G$ only
if $c(v)=0$. Terminate the search upon finding a vertex
$w$ with a pair of subsequent neighbors $\adj{w}{v_2}$
and $\adj{w}{v_1}=\nxt(\adj{w}{v_2})$ such that $c(v_2)=c(u_2)$ and
$c(v_1)=c(u_1)$,
i.e. $v_2\in P_2$ and $v_1\in P_1$. Backtrack along the
search tree from $w$ to find a minimal $u,w$-path $P_3$.
For each vertex $v\in P_3$, assign $c(v)\leftarrow d$, where $d\in
\{1,2,3\}-\{c(u_1),c(u_2)\}$.

Iterate through
$N(u)$ and $N(v_1)$ to find $\adj{u}{u_2}$ and
$\adj{v_1}{v_2}$.
Finally, to color the remaining vertices in $\text{Int}(C)-C-P_3$,
we make a recursive call
\vspace{-0.75pc}
\begin{enumerate}
\itemsep-0.25em
\item{with input $(u_1, v_1, \adj{{u_1}}{u}, w)$ to color
$\text{Int}(C_1)$, where $C_1=C[u_1,v_1]\cup P_3\cup v_1u\cup v_1w$,}
\item{with input $(u,  w, \adj{u}{u_2}, v_2)$ to color
$\text{Int}(C_2)$, where $C_2=C[v_2,u_2]\cup P_3\cup uu_2\cup wv_2$,}
\item{and with input $(v_1,  w_1, \adj{{v_1}}{v_2}, w_2)$
to color $\text{Int}(C_3)$, where $C_3=C[v_1,v_2]\cup v_1v_2$.}
\end{enumerate}
\end{algorithm}

Let $G$ be a triangulated plane graph and
let $C=v_1,v_2,v_3$ be the outer triangle of $G$ labeled in clockwise order.
We may compute a path $3$-coloring $c$ of $G$ as follows.
Create a length $n$ integer array $c$ and initialize each entry to zero.
Assign $c(v_1)\leftarrow 1$,
$c(v_2)\leftarrow 2$, and $c(v_3)\leftarrow 2$. Finally, apply
Algorithm~\ref{A:poh_bfs}
with input $G$, $c$, and
$(v_1, v_1, \adj{{v_1}}{v_2}, v_3)$.

Unfortunately, Algorithm~\ref{A:poh_bfs}
is not linear. Consider the sequence of ``pyramid graphs''
$\{A_k\}_{k\in\mathbb{N}}$ depicted in
Figure~\ref{F:pyramid}.
Fix $k\in\mathbb{N}$ and note that
$n=n(A_k)=k(k+1)/2+3$.
Assume that
the outer triangle is $2$-colored such that the top vertex is
assigned a color distinct from the bottom two. At recursive depth $i$,
Algorithm~\ref{A:poh_bfs} will perform a breadth first search of the
pyramid-shaped interior  subgraph with sides of length $r=k-i$, starting
from the vertex in the bottom left corner. The search will hit all
$r(r+1)/2$ vertices of the interior pyramid.
Therefore the total number of operations performed will be
\[
    \Omega\left( \sum_{r=1}^k\frac{r(r+1)}{2} \right)
    =\Omega(k^3)
    =\Omega(n^{3/2}).
\]

The correctness of Poh's proof, however, relied only on
locating an induced $u,w$-path.
Algorithm~\ref{A:poh_linear} describes a linear time implementation
of Poh's algorithm that locates and colors an induced $u,w$-path that is not
always of minimal length.

For a subraph $H$ of $G$, define $N(H)$ to be the
vertices in $G-H$ with a neighbor in $H$.
For $P_1=C[u_1,w_1]$ let $p_1:N(P_1)\to V(P_1)$ be the function that
maps each vertex to its furthest clockwise neighbor along $P_1$,
i.e. $V(C[p_1(v),w_1])\cap N(v)=\{p_1(v)\}$.

\begin{algorithm}\label{A:poh_linear} Path $3$-Color (Neighbor Trace)

\textbf{Input.} Let $C$ be an induced cycle
in a weakly triangulated plane
graph $G$ represented via adjacency lists.
Let $c$ be a length $n$ array
representing a $2$-coloring of $C$ such
that each color class induces a nonempty path,
respectively $P_1=C[u_1,w_1]$ and
$P_2=C[w_2,u_2]$, where $u_1,u_2,w_1,w_2\in C$. Assume that $c(v)=0$
for each $v\in\text{Int}(C)-C$.
Let $S$ be a length $n$ integer array and let $\ell_1$ be an integer
such that for each $v\in\text{Int}(C)-C$ we have $S(v)=\ell_1$ if and only if
$v\in N(P_1)$.

The concrete input will be $G$, $c$, and $S$,
along with the ordered pair $(u_1, \adj{{u_1}}{u_2}, \ell_1)$.

\textbf{Output.} For each vertex $v\in\text{Int}(C)-C$ a color in
$\{1,2,3\}$ will be
assigned to $c(v)$ such that $c$ represents a path $3$-coloring of
$\text{Int}(C)$ extending the original $2$-coloring of $C$.
Moreover, if $v\in \text{Int}(C)-C$ has a neighbor $u\in C$,
then $c(v)\ne c(u)$.

\textbf{Procedure.} Assign $\adj{u_1}{u}\leftarrow\nxt(\adj{u_1}{u_2})$.

\textbf{Base case.}
If $c(u)\ne 0$, then
$u=w_2$ or $u=w_1$. Thus $C$ is a face and we are done. 

\textbf{Recursive case.}
Suppose that $c(u)=0$, i.e. $u\in\text{Int}(C)-C$.
Let $d\in \{1,2,3\}-\{c(u_1),c(u_2)\}$.
Let $\ell_3=\max_{v\in G}S(v)+1$. We will
construct an induced $u,w$-path $P_3=v_1,v_2,\ldots, v_j$
such that $v_1,v_2,\ldots,v_j\in N(P_1)$,
and color each $v\in P_3$ with $c(v)\leftarrow d$.
We'll also mark each $v\in N(P_3)- V(C)$
with $S(v)\leftarrow\ell_3$,
and make recursive calls to color $\text{Int}(C)-C-P_3$.
It may be useful
to refer to Figures~\ref{F:poh_linear_1} and \ref{F:poh_linear_2}.

\textbf{Step~1.}
Assign $j\leftarrow 1$ and $v_j\leftarrow u$; here $j,v_j$ store
the end of the path $P_3$ that we've constructed so far.
Set $v_0\leftarrow u_2$ so that $v_{j-1}$ is defined for $j=1$.
Assign $i\leftarrow 1$ and $\adj{v_i}{s}\leftarrow \adj{v_i}{u_2}$;
here $i,\adj{v_i}{s}$ store the last edge $v_is$ that was visited
where $v_i\in P_3$ and $s\in P_2$.

\textbf{Loop~2.} We'll build the path $P_3$, adding one vertex per
iteration.
Assign $c(v_j)\leftarrow d$.
Find $\adj{v_j}{v_{j-1}}$ in $N(v_j)$ and set
$\adj{v_j}{v}\leftarrow \nxt(\adj{v_j}{v_{j-1}})$.
Set $y\leftarrow\text{NULL}$; here
$y$ will store the first neighbor of $v_j$
counter-clockwise from $v_{j-1}$ that is in
$N(P_1)- V(C)$ (if any).
Set $\adj{v_j}{t}\leftarrow\text{NULL}$; here
$\adj{v_j}{t}$ will store the last edge $v_jt$ encountered
such that $t\in P_1$ (if any).

\textbf{Loop~2.1.} We'll first consider the neighbors of
$v_j$ between
$v_{j-1}$ and $p_1(v_j)$ counter-clockwise. Each iteration
will handle the current neighbor $\adj{v_j}{v}$.
We'll make a recursive call for each
induced cycle $C_1$ we discover with $V(C_1)\subseteq V(P_2)\cup V(P_3)$.
Refer to Figure~\ref{F:poh_linear_1}.

\textbf{Case~2.1.1.} Suppose that $c(v)=0$, i.e. $v\in\text{Int}(C)-C$.
If $S(v)=\ell_1$, i.e. $v\in N(P_1)$, and $y=\text{NULL}$, then set
$y\leftarrow v$. Set $S(v)\leftarrow \ell_3$ and
$\adj{v_j}{v}\leftarrow\nxt(\adj{v_j}{v})$.
Repeat Loop~2.1.

\textbf{Case~2.1.2.} Suppose that $c(v)=c(u_2)$, i.e. $v\in P_2$.
Make a recursive call with input $(v_i, \adj{v_i}{s}, \ell_3)$
to color $\text{Int}(C_1)$, where
$C_1=P_3[v_i,v_j]\cup C[v,s]\cup v_is\cup v_jv$;
see Figure~\ref{F:poh_linear_1} (middle).
Assign $i\leftarrow j$, $\adj{v_i}{s}\leftarrow \adj{v_j}{v}$, and
$\adj{v_j}{v}\leftarrow\nxt(\adj{v_j}{v})$. Repeat Loop~2.1.

\textbf{Case~2.1.3.} Suppose that $c(v)=c(u_1)$, i.e. $v=p_1(v_j)\in P_1$.
Assign $\adj{v_j}{t}\leftarrow \adj{v_j}{v}$ and
$\adj{v_j}{v}\leftarrow\nxt(\adj{v_j}{v})$. Break Loop~2.1 and proceed to
Loop~2.2.

Note that if $y=\text{NULL}$, then $v_j=w$. To see this, observe that
since $v\in P_1$,
$\prv_{v_j}(v)\in N(P_1)$,
and $\prv_{v_j}(v)\not\in P_1$, we must have
$\prv_{v_j}(v)\in C-P_1=P_2$.

\textbf{Loop~2.2.} We'll now consider the
neighbors of $v_j$ between $p_1(v_j)$ and $v_{j-1}$ counter-clockwise.
Each iteration will handle the current neighbor $\adj{v_j}{v}$.
We'll make a recursive call for each
induced cycle $C_1$ we discover with $V(C_1)\subseteq V(P_1)\cup V(P_3)$.
Observe $\adj{v_j}{t}\ne\text{NULL}$.

\textbf{Case~2.2.1.} Suppose that $c(v)=0$, i.e. $v\in\text{Int}(C)-C-P_3$.
Assign $S(v)\leftarrow \ell_3$ and $\adj{v_j}{v}\leftarrow\nxt(\adj{v_j}{v})$.
Repeat Loop~2.2.

\textbf{Case~2.2.2.} Suppose that $c(v)\ne 0$, i.e. $v\in C$ or
$v\in P_3$. Make a recursive
call with input $(v_j, \adj{v_j}{t}, \ell_3)$ to color $\text{Int}(C_1)$,
where both the definition of $C_1$ and the next steps to take depend
on $c(v)$. Refer to Figure~\ref{F:poh_linear_2}.

If $c(v)=c(u_1)$, i.e. $v\in P_1$, then
$C_1=C[v,t]\cup v_j\cup v_jt\cup v_jv$.
Assign $\adj{v_j}{t}\leftarrow\adj{v_j}{v}$ and
$\adj{v_j}{v}\leftarrow\nxt(\adj{v_j}{v})$. Repeat Loop~2.2.

Otherwise,
$v=v_{j-1}$ (either $j>1$ and $v\in P_3$, or $j=1$ so
$v=u_2\in P_2$ and $t=u_1$).
Then $C_1=C[p_1(v),t]\cup P_3[v,v_j]\cup vp_1(v)\cup v_jt$.
Break Loop~2.2 and proceed to Step~2.3. 

\textbf{Step~2.3.} If $y\ne\text{NULL}$, then
assign $j\leftarrow j+1$, $v_j\leftarrow y$, and
repeat Loop~2. Otherwise, $v_j=w$ and we are done.
\end{algorithm}

Algorithm~\ref{A:poh_linear} is always an induced subgraph of $G$.
Suppose that $v_kv_j\in E(G)$ with $0<k<j-1$. Observe that
\[
    D = C[u_2,p_1(v_{j-1})]\cup P_3[v_1,v_{j-1}]\cup u_2v_1\cup 
        v_{j-1} p_1(v_{j-1})
\]
is a cycle in $G$ with $v_{k-1},v_k,v_{k+1}\in D$ and
$v_{j}\not\in\text{Int}(D)$, see Figure~\ref{F:poh_linear_2} (right).
Therefore $v_kv_j\not\in\text{Int}(D)$ and
$v_kv_j$ lies between $v_{k-1}$ and $v_{k+1}$ counter-clockwise
in $N(v_k)$. But $v_{k+1}$ is the first neighbor
in $N(P_1)$ counter-clockwise from $v_{k-1}$ around $v_k$, a contradiction.

Given a triangulated plane graph $G$ represented via adjacency lists,
we can apply
Algorithm~\ref{A:poh_linear} as follows. First, create length $n$ integer
arrays for $c$ and $S$, initializing each entry to zero.
Let $C=v_1,v_2,v_3$ be the outer triangle of $G$,
labeled in clockwise order.
Color $c(v_1)\leftarrow 1$, $c(v_2)\leftarrow 2$, and
$c(v_3)\leftarrow 2$.
Iterate through $N(v_1)$ and mark $S(v)\leftarrow 1$ for each
neighbor $v$ of $v_1$.
Then $G$, $c$, $S$,
$(v_1, \adj{v_1}{v_3}, 1)$ form a valid input for
Algorithm~\ref{A:poh_linear}.

During Algorithm~\ref{A:poh_linear} we iterate through
$N(v)$ for each $v\in G$ exactly twice: once
to locate $\adj{{v_j}}{v_{j-1}}$ when
$v_j=v$ is colored and added to a path $P_3$ in Loop~2,
and once to iterate through $N(v_j)$ in Loops~2.1 and 2.2.
Therefore the time complexity is
$\mathcal{O}(m)=\mathcal{O}(n)$.

\section{Path List-Coloring}\label{S:path_choose}

In this section we describe a linear time algorithm to path color
plane graphs such that each vertex receives a color from a specified list.
Hartman showed that this is always possible when each vertex is given a
list of $3$ colors~\cite[Thm.~4.1]{Har1997}. Around the same
time \v{S}krekovski proved a
weaker result using the same coloring
strategy~\cite[Thm.~2.2b]{Skr1999}.

For those familiar
with Hartman's proof: if $x=z$, then our $G,x,y$ match
those in \cite[Lemma.~4.2]{Har1997}, but our
$G$ is always biconnected;
we follow the same iterative procedure to color a path
$P$ clockwise from $x$ along $C$, but we proceed inductively,
one edge at a time, and simultaneously remove
$P$ as it is colored. If $x\ne z$, then $z$ is
the furthest clockwise end of the path $P$ being colored; the
the rest of $P$
(including the original ``$x$'') has been removed. The only way in
which our algorithm differs from Hartman's is that if $x$
immediately follows $y$ clockwise around $C$, then we swap $x$ and $y$
(see Case~1 below).

Given a graph $G$ and a coloring $c$ of $G$, for each $v\in G$ we
define $\text{deg}_c(v)$ to be the number of neighbors of $v$ that share a color
with $v$. Equivalently, $\text{deg}_c(v)$ is the degree of $v$ in the subgraph
of $G$ induced by the color class of $c(v)$.

\begin{lemma}\label{L:hartman3}
Let $G$ be a biconnected, weakly triangulated plane graph with outer face
$C$. Let $x,y,z\in C$ be vertices (not necessarily distinct) such that
$z\in C[x,y]$. Let $L$ be a list assignment of $G$ such that
\begin{align*}
    |L(v)| &= 1 \text{ for } v\in\{x,y,z\},\\
    |L(v)| &\ge 2 \text{ for } v\in C-\{x,y,z\},\\
    |L(v)| &\ge 3 \text{ for } v\in G-C,
\end{align*}
and if $v\in C[x,z]-z$, then $L(v)\cap L(z)=\emptyset$.
There exists a path $L$-coloring of $G$ such that $\text{deg}_c(x)\le 1$,
$\text{deg}_c(y)\le 1$, and $\text{deg}_c(z)\le 1$. Moreover,
if $z=y$, or if $C[z,y]=z,y$ and $L(z)\cap L(y)=\emptyset$,
then $\text{deg}_c(z)=0$.
\end{lemma}

\begin{proof}
Suppose that $m=|E(G)|\le 1$. Then $G=C$. We define a path
$L$-coloring $c$ of $G$ as follows.
Let $c(x)\in L(x)$, $c(y)\in L(y)$, and $c(z)\in L(z)$ be the colors in
each respective list.
If $m=0$, then $n(G)=1$ and $c$ is trivially a path $L$-coloring.
Otherwise $m=1$ and $n(G)= 2$. If $x\ne y$, then $c$ is a
path $L$-coloring of $G$ with the constraints of the lemma.
Otherwise the remaining
$v\in G-y$ satisfies $|L(v)|\ge 2$, and we define
$c(v)\in L(v)-\{c(y)\}$.

We proceed by induction on $m$, the number of edges. Let
$u_1,u_2,\ldots,u_k$ label the neighbors of $z$ in counter-clockwise
order such that $u_1$ is the vertex immediately counter-clockwise
from $z$ around $C$, and $u_k$ is the vertex clockwise from $z$ around $C$.
In each of the subsequent cases we will apply the lemma separately
to one or two subgraphs $G_1,G_2$ of $G$, with corresponding labeled
outer face vertices $x_i,y_i,z_i\in G_i$ for $i=1,2$.

\textbf{Case~1.}
Suppose that $u_1=y$. Note that $z=x$ since $z\in C[x,y]$. Therefore
$V(C[z,y])=V(C)$ and, in particular, $|V(C[z,y])|\ge 3$, so $C[z,y]\ne z,y$.
Apply the lemma to find a path $L$-coloring $c$ of $G_1=G$ with
$x_1=y$, $y_1=x$, and $z_1=y$.

\textbf{Case~2.}
Suppose that $u_1\ne y$ and $z=x$. Then $u_1\in C-C[x,z]$
and $|L(u_1)|\ge 2$. Pick $d\in L(u_1)- L(z)$. Define
$L'(u_1)=\{d\}$ and $L'(v)=L(v)$ for each $v\in G-u_1$. Apply the
lemma to find a path $L'$-coloring of $G_1=G$ with $x_1=u_1$,
$y_1=y$, and $z_1=z$.

\textbf{Case~3.}
Suppose that $u_1\ne y$ and $z\ne x$. 
Our strategy will be to apply the inductive hypothesis to
the \defterm{blocks} (maximal biconnected subgraphs) of $G-zu_1$.
Because $u_1\in C[x,z]$, it is guaranteed that $L(u_1)\cap L(z)=\emptyset$.
Thus any path $L$-coloring of $G-zu_1$ is also a path $L$-coloring
of $G$.

\textbf{Case~3.1.}
Suppose that $u_2\in G-C$. Define $L'(u_2)=L(u_2)- L(z)$ and
$L'(v)=L(v)$ for each $v\in G-u_2$. Note that $|L'(u_2)|\ge |L(u_2)|-1\ge 2$.
Let $C_1$ be the outer face of $G_1=G-zu_1$,
and observe that $C_1[x,z]$ is equal to $C[x,z]$ with the edge $u_1z$ removed
and the path $u_1,u_2,z$ added. Since $|L'(u_2)|\ge 2$ and $L'(u_2)\cap
L'(z)=\emptyset$, we may apply the inductive hypothesis
to find a path $L'$-coloring of $G_1$ with $x_1=x$, $y_1=y$, $z_1=z$.

\textbf{Case~3.2.}
Suppose that $u_2\in C$. Observe that $u_2$ is a \defterm{cut-vertex} of
$G-zu_1$, i.e. $G-zu_1-u_2$ is disconnected.
Define $C_1=C[u_2,u_1]\cup u_1u_2$ and
$C_2=C[z,u_2]\cup zu_2$. Let $G_1=\text{Int}(C_1)$ and $G_2=\text{Int}(C_2)$.
The subgraphs $G_1$ and $G_2$ are the two blocks of
$G-zu_1$. Note that if $k=2$, then $G_1=G-z$ and $G_2=z,u_2$.

In each subsequent case we will apply the inductive
hypothesis to find a path $L$-coloring $c_1$ of $G_1$ and a path
$L$-coloring $c_2$ of $G_2$ such that $c_1(u_2)=c_2(u_2)$. Let
$c$ be the $L$-coloring of $G$ defined by $v\mapsto c_1(v)$ for $v\in G_1$
and $v\mapsto c_2(v)$ for $v\in G_2$.
Observe that $\text{deg}_c(v)=\text{deg}_{c_1}(v)$
for each $v\in G_1-u_2$, $\text{deg}_c(v)=\text{deg}_{c_2}(v)$ for each
$v\in G_2-u_2$, and
$\text{deg}_c(u_2)=\text{deg}_{c_1}(u_2)+\text{deg}_{c_2}(u_2)$.
To show that $c$ is a path $L$-coloring of $G$ it suffices to show that
$\text{deg}_{c}(u_2)\le 2$. We'll also need to show the
$\text{deg}_c$ constraints for $x,y,z$, but often these will follow
immediately from the inductive hypothesis.

Let $G$ be a planar graph and $L$ a list assignment such
that $|L(v)|\ge 3$ for each $v\in G$. Compute a planar embedding and add
edges
to produce a triangulated plane graph $G'$. Pick $u\in G'$ on the outer face
and $d\in L(u)$. Define the list assignment $L'$ by
$L'(u)=\{d\}$ and $L'(v)=L(v)$ for $v\in G'-u$.
By Lemma~\ref{L:hartman3} there exists a path $L'$-coloring $c$ of $G'$,
and thus a path $L$-coloring of $G$.
So Theorem~\ref{T:planar3} follows immediately from 
Lemma~\ref{L:hartman3}.

The proof of Lemma~\ref{L:hartman3} may be
implemented as a linear time algorithm for plane graphs.
For $v\in G$ and $u\in N(v)$, we will assume that
$\nxt(\adj{v}{u})$, $\prv(\adj{v}{u})$, and $\adj{u}{v}$ can be
computed in constant time from the entry $\adj{v}{u}$;
see augmented adjacency lists in Section~\ref{S:representation}.

\begin{algorithm}\label{A:hartman_impl} Path $3$-Choose

\textbf{Input.} Let $C$ be a cycle or length $1$ path in a
weakly triangulated plane graph $G$ represented via augmented
adjacency lists.
Let $x,y,z\in C$ be such that $z\in C[x,y]$.

Let $L$ be a length $n$ array of lists of colors
such that for $v\in\{x,y,z\}$ the list $L(v)$ has length one,
for $v\in C-\{x,y,z\}$ the list $L(v)$ has length two
or three, and for $v\in \text{Int}(C)-C$ the list
$L(v)$ has length three. Furthermore, for each $v\in C[x,z] - z$ assume
that $L(v)$ does not contain the color in $L(z)$.

Let $B,F$ be length $n$ arrays such that for each $v\in C$ we have
$B(v)=\adj{v}{b}$ and $F(v)=\adj{v}{f}$, where
$b$ is the vertex immediately counter clockwise
from $v$ around $C$,
and $f$ is the vertex
immediately clockwise from $v$ around $C$.

Let $S$ be a length $n$ integer array such
that, for $v\in\text{Int}(C)$, $S(v)\ne 0$ if and only if $v\in C$, and
$S(v)=S(x)$ if and only if $v\in C[x,z]-z$ (or $v=x=z$).
Let $\text{max}(S)=\text{max}_{v\in G} S(v)$ and
$m_C=m(\text{Int}(C))$.
If $z\ne x$, then define $\ell=\text{max}(S)$.
If $z=x$ and $C[y,x]\ne y,x$, then define $\ell=\text{max}(S)+1$.
Otherwise, define $\ell=\text{max}(S)+2$. Assume that
$\ell < 2(m-m_C) + 4$.

Let $M$
be a length $2m+2$ integer array such that if $v\in C$,
then $M(S(v))=S(y)$ if and only if $v\in C[z,y]$.

The concrete input will be $G$, $L$,
$B$, $F$, $S$, $M$, and the tuple $(x,y,z)$.

\textbf{Output.} For each $v\in\text{Int}(C)$, all but one color will be
removed from the list $L(v)$. The remaining color in each list will represent
a path $L$-coloring of $\text{Int}(C)$
such that $\text{deg}_c(x)\le1$, $\text{deg}_c(y)\le1$, and
$\text{deg}_c(z)\le1$. If $z=y$, or if $C[z,y]=z,y$ and $L(z)$ did
not contain the color in $L(y)$, then $\text{deg}_c(z)=0$. Moreover,
afterwards $\text{max}(S)\le\ell+2(m_C-1)$.

\textbf{Procedure.} Assign $\adj{z}{u_1}\leftarrow B(z)$. Our strategy
will follow the proof of Lemma~\ref{L:hartman3}.

\textbf{Base case.} If $B(z)=F(z)$, then $C=z,u_1$
is a length $1$ path. If $u_1\ne x$ and $u_1\ne y$, remove the
color in $L(z)$ from $L(u_1)$, if it exists, then remove further colors
until one color remains. Note that
$m_C=1$ and $\text{max}(S)\le\ell+ 2(m_C-1)=\ell$ by definition.

\textbf{Recursive case.} Suppose that $B(z)\ne F(z)$.
Note that $n(C)>2$ and therefore $C$ is a cycle. Assign
$\adj{z}{u_2}\leftarrow\nxt(\adj{z}{u_1})$. It will be immediately apparent
that $\text{max}(S)\le\ell+2(m_C-1)$ after Cases~1, 2,
and 3.1, so we will only argue that this bound is satisfied after Case~3.2.
It may be useful to refer to
Figures~\ref{F:hartman_1}, \ref{F:hartman_3_2}, and
\ref{F:hartman_3_2_3}.

\textbf{Case~1.} Suppose that $u_1=y$. Then $z=x$, since $z\in C[x,y]$.
Set $S(x)\leftarrow \text{max}(S)+1$ and
$S(y)\leftarrow S(x)$.
Assign $M(S(x))\leftarrow S(x)$.
Make a recursive call with the input $(y, x, y)$.

\textbf{Case~2.} Suppose that $z=x$ and $u_1\ne y$. 
Remove the color in $L(z)$ from $L(u_1)$, if it exists, then remove
further colors until one color remains.
Assign $S(u_1)\leftarrow \text{max}(S)+1$
and $M(S(u_1))\leftarrow S(u_1)$,
and make a recursive call with input $(u_1, y, z)$.

\textbf{Case~3.} Suppose that $z\ne x$ and $u_1\ne y$.
Remove $zu_1$ by assigning $F(u_1)\leftarrow\prv(\adj{u_1}{z})$
and $B(z)\leftarrow\nxt(\adj{z}{u_1})$;
refer
to Figure~\ref{F:hartman_1} (right),
Figure~\ref{F:hartman_3_2}, and Figure~\ref{F:hartman_3_2_3}.

\textbf{Case~3.1.} Suppose that $S(u_2)=0$, that is, $u_2\in
\text{Int}(C)-C$. Assign $S(u_2)\leftarrow S(x)$ and initialize
$B(u_2)\leftarrow\adj{u_2}{u_1}=\nxt(\adj{u_2}{z})$ and
$F(u_2)\leftarrow\adj{u_2}{z}$;
refer to Figure~\ref{F:hartman_1} (right).
Remove the color in $L(z)$ from
$L(u_2)$.
Make a recursive call with the same input $(x, y, z)$.

\textbf{Case~3.2.} Suppose that $S(u_2)\ne 0$, that is, $u_2\in C$. Just as in
Case~3.2 of the proof of Lemma~\ref{L:hartman3}, we will separately consider
the two blocks $G_1$ and $G_2$ of $\text{Int}(C)-zu_1$.
Note that $m_C-1=m(G_1)+m(G_2)$.

As we've already removed the edge $zu_1$ by
adjusting $B(z)$ and $F(u_1)$, it remains
to ``split'' the
neighborhood of $u_2$ at the edge $\adj{u_2}{z}$ such that the recursive
call on $G_1$ considers only the neighbors of $u_2$ counter-clockwise
from $z$, and the call
on $G_2$ considers $z$ and all neighbors clockwise from $z$;
refer
to Figure~\ref{F:hartman_3_2} and
Figure~\ref{F:hartman_3_2_3}.

Store $\adj{u_2}{b}\leftarrow B(u_2)$ and
$\adj{u_2}{f}\leftarrow F(u_2)$.
To represent $G_1$, assign $B(u_2)\leftarrow\nxt(\adj{u_2}{z})$
and $F(u_2)\leftarrow\adj{u_2}{f}$.
To represent $G_2$,
assign $B(u_2)\leftarrow\adj{u_2}{b}$
and $F(u_2)\leftarrow\adj{u_2}{z}$.

\textbf{Case~3.2.1.} Suppose that $S(u_2)=S(x)$, i.e. $u_2\in C[x,z]$. Make a
recursive call on $G_2$ with input $(x, y, z)$;
afterwards $\text{max}(S)\le\ell + 2m(G_1)-2$.
Assign $S(u_2)\leftarrow\text{max}(S)+1$ and
$M(S(u_2))\leftarrow S(u_2)$, and make a recursive call
on $G_1$ with input $(u_2, u_2, u_2)$.
Finally, observe that
$\text{max}(S)\le\ell + 2m(G_1)-2 + 1 + 2m(G_2)-1<\ell+2(m_C-1)$.

\textbf{Case~3.2.2.} Suppose that $z\ne x$ and $S(u_2)\ne 0$, but
$S(u_2)\ne S(x)$ and $M(S(u_2))\ne S(y)$. In other words, suppose that
$u_2\in C[y,x]-x-y$.
First remove the color in $L(z)$ from $L(u_2)$, if it exists, then remove
further colors until one remains. Set $S(u_2)\leftarrow S(x)$.
Make a recursive call on $G_1$ with input $(x, u_2, x)$;
afterwards $\text{max}(S)\le\ell +2m(G_1)$.
Set $S(u_2)\leftarrow\text{max}(S)+1$ and
$M(S(u_2))\leftarrow S(u_2)$, and
make a recursive call on $G_2$ with input $(u_2, y, z)$.
Finally, observe that
$\text{max}(S)\le\ell + 2m(G_1) + 1 + 2m(G_2)-2<\ell+2(m_C-1)$.

\textbf{Case~3.2.3.} Suppose that $z\ne x$ and $M(S(u_2))=S(y)$, i.e.
$u_2\in C[z,y]$. There are
two cases to consider.

\textbf{Case~3.2.3.1.} Suppose that the color in $L(z)$ is in $L(u_2)$. Remove
all colors from $L(u_2)$ except for the color in $L(z)$.
Make a recursive call on $G_1$ with input $(x, y, u_2)$;
afterwards $\text{max}(S)\le\ell + 2m(G_1)-2$.
Assign
$S(z)\leftarrow\text{max}(S)+1$, $S(u_2)\leftarrow S(z)$,
and $M(S(z))\leftarrow S(z)$. Make a
recursive call on $G_2$ with input $(u_2, z, u_2)$. Finally, observe that
$\text{max}(S)\le\ell + 2m(G_1)-2 + 1 + 2m(G_2) - 1<\ell+2(m_C-1)$.

\textbf{Case~3.2.3.2.} Suppose that the color in $L(z)$ is not in $L(u_2)$.
Assign $M(S(x))\leftarrow S(y)$. Make a recursive call on $G_1$
with input $(x, y, x)$; afterwards $\text{max}(S)\le\ell + 2m(G_1)$.
Assign $S(z)\leftarrow\text{max}(S)+1$, $S(u_2)\leftarrow S(z)$, and
$M(S(z))\leftarrow S(z)$. Make a
recursive call on $G_2$ with input $(u_2, z, u_2)$. Observe
$\text{max}(S)\le\ell + 2m(G_1) + 1 + 2m(G_2) - 1=\ell+2(m_C-1)$.

Note that this is the only case where
$M(S(v))$ is set a value other than $S(v)$.
Setting $M(S(x))\leftarrow S(y)$ effectively ``joins''
$C[x,u_1]$ onto $C[u_2,y]$ to represent $C_1[z_1,y_1]$ in $G_1$,
without having to re-mark each vertex in $C[x,u_1]$ with $S(y)$;
see Figure~8.
\end{algorithm}

Let $G$ be a triangulated plane graph
represented by augmented adjacency
lists. Let $L$ be a length $n$ array of color lists of length $3$,
representing a list assignment of $G$. We may path $L$-color $G$ using
Algorithm~\ref{A:hartman_impl} as follows.

Create length $n$ arrays $B,F$ and initialize $B(v)$
and $F(v)$ for each $v\in C$ on the outer face of $G$.
Create a length $n$ integer array
$S$ and initialize $S(v)\leftarrow 1$ for each $v\in C$ and
$S(v)\leftarrow 0$ for each $v\in G-C$. Pick any $u\in C$,
assign $S(u)\leftarrow 2$, and remove all but one color from $L(u)$.
Create a length $2m+2$ array of integers $M$ and initialize
$M(i)\leftarrow i$ for each $i\in\{0,1,2\}$.
Finally, apply Algorithm~\ref{A:hartman_impl} with the input $G$, $L$,
$B$, $F$, $S$, $M$, and $(u, u, u)$. The remaining color in each
list in $L$ will represent a path $L$-coloring of $G$.

Every recursive case in Algorithm~\ref{A:hartman_impl} performs a fixed number
of constant time operations. Each case removes one edge from the graph
representation,
except for Case~1 and Case~2. In Case~1 a single recursive call is made
with an input that will satisfy Case~2. In Case~2 a recursive
call is made with an input that will not itself satisfy Case~1 or Case~2.
Therefore the number of operations performed
is $\mathcal{O}(m)=\mathcal{O}(n)$. See Figures~\ref{F:hartman_impl},
\ref{F:hartman_impl_cont}, and \ref{F:hartman_impl_comp} for a concrete
example of Algorithm~\ref{A:hartman_impl}.

\section{Experimental Performance and Parallelism}\label{S:performance}

A C implementation of each algorithm is available~\cite{Bro2017}.
For each $i$ from $3\ldots 7$, a uniform random sample of $100$
plane triangulations of order $10^i$ was
generated. Each algorithm was run on a each set of samples,
see the timings in Figure~\ref{F:benchmark} and the plot
in Figure~\ref{F:plot}.

Plane triangulations were sampled using the method of
Poulalhon and Schaeffer~\cite{Pou2006}.
The vertices were randomly re-labeled in each sampled graph, and the
corresponding adjacency list arrays were re-ordered in memory such that
the list for newly-labeled vertex $0$ came first in memory, followed
by the list for vertex $1$, and so on. The
benchmark results therefore represent each algorithm's
performance on a set of uniformly sampled plane triangulations,
each with a
uniformly sampled representation layout in memory.
The list assignments for Algorithm~\ref{A:hartman_impl} were uniformly
drawn from a set of six colors.

A breadth-first search (BFS) implemented with
a circular array FIFO queue was run on the same set of graphs
as a baseline
algorithm that hits every half-edge of a graph exactly once.
All binaries 
were compiled with Clang 19.1.7 and run on a Linux 6.12.9 machine
with an x86\_64 Intel N100 processor.
Both source code and binaries are available~\cite{Bro2017}.

The performance of
Algorithm~\ref{A:hartman_impl} was similar to
Algorithm~\ref{A:poh_linear} on the sampled graphs, but
Algorithm~\ref{A:hartman_impl} required an
augmented adjacency list representation. For
situations where such a representation
is not immediately available, the time required by
Algorithm~\ref{A:hartman_impl} would also include
the time required by Algorithm~\ref{A:augment}.

Algorithm~\ref{A:poh_linear} and Algorithm~\ref{A:hartman_impl} perform
recursive calls that operate on
subgraphs that are disjoint apart from select vertices on their
respective outer faces. Therefore it is possible to maintain a
stack of
independent recursive frames and have a pool of threads operate on the frames
concurrently. The amount of parallelism possible with this method is highly
dependent on the structure of the graph. E.g. when
Algorithm~\ref{A:poh_linear} is run on a pyramid
graph from Figure~\ref{F:pyramid} there will never be more
than one recursive frame on the stack, and thus
no opportunity for parallel execution.

In the case of Algorithm~\ref{A:poh_linear} such parallelism can easily be
organized since
each frame writes only to vertices interior to the outer face of
its associated subgraph. Therefore the
implementation can maintain a shared lock-guarded stack from which
all threads push and pop recursive frames.
If no frames are
available, a thread must idle until either a new frame is pushed to the stack
by another thread or until
all threads are idle.

To reduce lock contention, each thread should also
maintain a
small local stack of frames, and only access the shared
stack when this local stack is full or empty.
For the implementation and hardware
used for benchmarks, the most optimal setup proved to be a
local stack of $16$ frames for each thread. If a local stack filled up,
$8$ frames were pushed to the
shared stack. If a local stack emptied, $8$ frames were popped from the
shared stack.

Algorithm~\ref{A:hartman_impl} is trickier to adapt to
parallel execution. The first difficulty to consider is that
the recursive calls made in
Algorithm~\ref{A:hartman_impl} relied on a sequential
execution order. If we save a local copy of
$S(v), B(v), F(v)$ for each $v\in\{x, y,z\}$ alongside
each frame, then the recursive calls in
Case~3.2.1 with $u_2=x$, Case~3.2.2,
Case~3.2.3.1, and Case~3.2.3.2 with $u_2=y$ become order independent.
Unfortunately, in Case~3.2.1 with $u_2\ne x$ and Case~3.2.3.2 with $u_2\ne y$,
the second recursive call will always depend on the reduced color list $L(u_2)$
produced by the first call.

The hurdle of dependent frames can be overcome by maintaining a shared
lock-guarded object pool
of frames and a stack of frame references. Recursive frames will be added to the
pool when they appear in the usual course of the algorithm, but will
only be pushed to the shared stack when they are ready to be
executed. For each vertex $v\in G$, maintain an optional reference
to a frame that will become ready when $v$ has been colored, i.e. has had
its color list reduced to length $1$. To allow for
multiple frames to await the coloring of a single vertex, each frame in the
pool will store an ``intrusive linked list,'' that is, an optional
reference to the next frame in line. When a frame is added to the pool and
it needs to await a vertex that has another frame waiting on it,
the new frame is added to the linked list of the existing frame.
When a vertex $v$ is colored, 
walk the linked list of frames waiting on $v$
and push a reference to each frame onto the shared stack.

Another important detail
is that each new face mark $\text{max}(S)+1$ assigned to $S$ must be unique
across all threads, or else we risk corruption and data races against
the array $M$.
Uniqueness across threads can be ensured by using a shared atomic
counter to track $\text{max}(S)$.
Contention can be minimized by having
threads reserve marks in chunks, rather than performing an
atomic fetch-add operation for each new mark.

In Case~3.2.1, if $u_2= x$, then $S(x)$ should be assigned a new mark
in the recursive frame handling the $G_2$ subgraph to
prevent future writes to $M(S(x))$ from
interfering with reads from $M(S(x))$ regarding the vertices on the
outer face of $G_1$ marked with $S(x)$; technically this is optional,
as the data race will never affect the outcome of the algorithm. In
Figure~\ref{F:hartman_impl} the mark assigned to the bottom
right vertex $x$ of the graph in the step at the bottom right of the
page would change from $4$ to $7$ in the $G_2$ block.
This would then ripple forward, with the next new mark being
an $8$, and so on.

Lock contention can be reduced the same as in
Algorithm~\ref{A:poh_linear} by having each thread maintain a local stack of
frames, but if a frame needs to await the coloring
of a vertex, then it must be added to the shared pool since any thread
may color that vertex. Moreover, if a frame colors a
vertex that another frame is waiting on, then the lock must be
acquired.

Benchmarks in Figure~\ref{F:benchmark_hartman_thread}
showed some benefit to the parallel
version of Algorithm~\ref{A:hartman_impl} when $n\ge 10^4$, with
significant performance improvements appearing for very large graphs.
